# Claude와 함께 코딩할 때 알아두면 좋은 보안 상식

> 보안을 전혀 몰라도 괜찮아요 — 이 가이드 하나로 흔한 실수를 미리 막을 수 있어요.
>
> HTML · CSS · JavaScript 로 웹페이지를 만드는 모든 분을 위한 안내서

---

## 이 가이드에서 다루는 내용

- 1장 — 비밀 정보(API 키, 비밀번호)를 코드에 넣지 않기

## 들어가며

Claude 같은 AI와 함께 코딩하면 정말 편리하죠. 몇 줄의 설명만으로도 그럴듯한 웹페이지가 뚝딱 만들어지니까요.

그런데 AI가 만들어준 코드에는 한 가지 함정이 있어요. **보안 설정을 빠뜨리거나 위험한 코드를 그대로 사용하는 경우가 생각보다 자주 있거든요.** AI가 나쁜 의도로 그런 건 아니에요. 그냥 질문한 기능을 만들어주다 보니, 아무도 "보안도 신경 써줘"라고 말 안 하면 그냥 넘어가버리는 거예요.

이 가이드는 보안 지식이 전혀 없어도 읽을 수 있도록 썼어요. 어려운 용어 대신 "이렇게 하면 왜 위험한지", "그럼 어떻게 하면 되는지"를 중심으로 설명할게요.

## 1. 비밀 정보를 코드에 넣지 마세요

가장 많이 발생하는 실수 중 하나예요. 'API 키', '비밀번호', '토큰' 같은 것들을 코드 안에 직접 써버리는 거예요.

### 왜 위험한가요?

코드는 눈에 보이는 것이에요. 특히 HTML이나 JavaScript 파일은 웹브라우저에서 누구나 열어볼 수 있어요. 비밀번호나 API 키가 거기 적혀 있다면, 그 페이지를 방문한 사람 누구나 그 정보를 가져갈 수 있어요.

> 💡 **API 키가 뭔가요?**
>
> 카카오 지도, 날씨 정보, ChatGPT 같은 외부 서비스를 내 웹사이트에서 쓰려면 그 서비스에 "나 허가받은 사용자야" 라고 증명해야 해요.
> 그 증명서 역할을 하는 비밀 코드가 바로 API 키예요. 이게 유출되면 다른 사람이 내 이름으로 그 서비스를 마구 사용해서 요금이 청구될 수 있어요.

### 어떻게 생긴 코드가 위험한가요?

❌ **이렇게 하면 안 돼요**

```javascript
// JavaScript 파일 안에...
const API_KEY = "sk-abcdef1234567890";
const PASSWORD = "mypassword123";

// 이 파일은 브라우저에서 누구나 볼 수 있어요!
```

✅ **이렇게 해야 해요**

```javascript
// API 키가 필요하다면 Claude에게
// 먼저 이렇게 물어보세요:

// "API 키를 클라이언트 코드에
//  노출하지 않으려면 어떻게 해야 해?"
```

### Claude에게 이렇게 요청해 보세요

- "이 기능에 API 키가 필요한데, 코드에 직접 넣으면 보안상 위험하다고 하던데 어떻게 처리해야 해?"
- "이 사이트를 GitHub에 올리고 싶은데 API 키가 유출될까봐 걱정돼. 어떻게 하면 돼?"

> 💡 **Vercel을 사용하고 있다면**
>
> Vercel에는 API 키를 코드 밖에서 안전하게 관리할 수 있는 **환경 변수(Environment Variables)** 기능이 있어요. 프로젝트 설정에서 API 키를 등록해두면, 코드에 직접 쓰지 않아도 사용할 수 있어요.
>
> 단, 이 방식은 **서버 함수(Serverless Functions)와 함께 써야 제대로 동작해요.** 일반 HTML/JS 파일에서 `process.env.API_KEY` 식으로 불러오려 하면 작동하지 않고, 오히려 값이 비어있거나 오류가 날 수 있어요. 서버 함수란 Vercel 서버에서 실행되는 코드로, API 키를 브라우저에 노출하지 않고 외부 서비스와 통신할 수 있게 해줘요.
>
> "Vercel 환경 변수로 API 키 관리하는 방법 알려줘"라고 Claude에게 물어보면 단계별로 안내해줄 거예요.

> 🚨 **이미 실수했다면?**
>
> 실수로 API 키가 포함된 파일을 GitHub나 인터넷에 올렸다면:
> 1. 즉시 해당 서비스에 로그인해서 그 API 키를 삭제(revoke)하고 새로 발급받으세요.
> 2. 파일에서 키를 제거한 뒤 다시 업로드하는 것만으로는 부족해요. 누군가 이미 봤을 수 있거든요.
> 3. 서비스에 따라 비용이 청구되었는지 확인해 보세요.

## 2. 사용자가 입력한 내용을 그대로 믿지 마세요

웹페이지에 입력창(텍스트박스)을 만들었다고 해봐요. 방문자가 이름을 입력하면 "안녕하세요, 홍길동님!" 같은 메시지를 보여주는 거예요. 아주 자연스러운 기능이죠. 그런데 여기에 함정이 있어요.

### XSS 공격 — 입력창에 코드를 넣으면?

나쁜 사람이 이름 칸에 "홍길동" 대신 이런 걸 입력하면 어떻게 될까요?

```html
<script>alert("해킹!");</script>
```

코드가 그대로 실행돼버려요. 이걸 XSS(Cross-Site Scripting) 공격이라고 해요. 단순히 팝업 창 하나가 뜨는 게 아니라, 악용하면 방문자의 로그인 정보를 훔쳐가거나 이상한 사이트로 리다이렉트 시킬 수도 있어요.

> 💡 **XSS가 뭔가요?**
>
> Cross-Site Scripting의 줄임말이에요. 공격자가 웹페이지에 악성 스크립트를 심어서, 그 페이지를 방문한 다른 사람들에게 피해를 주는 공격이에요.
> 이름, 댓글, 검색어 등 사용자 입력을 받는 곳이라면 어디서든 발생할 수 있어요.

### 어떻게 생긴 코드가 위험한가요?

❌ **위험한 코드**

```javascript
const name = input.value;
// HTML에 그대로 넣어버림
div.innerHTML = '안녕, ' + name;
```

✅ **안전한 코드**

```javascript
const name = input.value;
// 텍스트로만 처리 (HTML 해석 안 함)
div.textContent = '안녕, ' + name;
```

핵심은 `innerHTML` 대신 `textContent`를 쓰는 거예요. `innerHTML`은 HTML 태그를 그대로 해석해서 실행해버리지만, `textContent`는 그냥 글자로만 처리해요.

### Claude에게 이렇게 요청해 보세요

- "사용자가 입력한 내용을 화면에 보여주는 코드인데, XSS 공격에 안전한지 확인해줘."
- "innerHTML 쓰는 부분이 있으면 다 찾아서 안전한 방식으로 바꿔줘."

## 3. 외부 파일이나 링크를 함부로 가져오지 마세요

웹페이지를 만들다 보면 외부 라이브러리(부트스트랩, jQuery 같은 것들)를 CDN이라는 방식으로 가져올 때가 많아요. 또 남의 블로그에서 찾은 코드를 그대로 복사해서 붙여넣기도 하죠.

### 신뢰할 수 없는 CDN 사용

CDN은 외부 서버에 있는 파일을 내 페이지에서 직접 불러오는 방식이에요. 그런데 그 서버가 해킹당하거나 악성 코드로 교체되면, 내 페이지를 방문한 모든 사람이 피해를 입어요.

❌ **출처 불명의 CDN**

```html
<!-- 어디서 찾은 건지 모르는 URL -->
<script src="https://cdn.unknown-site.xyz/jquery.js"></script>
```

✅ **공식 CDN 사용**

```html
<!-- 공식 사이트에서 확인한 URL + integrity 속성 -->
<script src="https://code.jquery.com/jquery-3.7.1.min.js"
        integrity="sha256-/JqT3SQfawRcv/BIHPThkBvs0OEvtFFmqPF/lYI/Cxo="
        crossorigin="anonymous"></script>
```

공식 CDN을 사용할 때는 `integrity` 속성도 함께 추가해야 해요. 파일이 변조되었는지 자동으로 검사해주는 안전장치예요. 공식 사이트에서 코드를 복사하면 대부분 이 값이 함께 제공돼요.

### 블로그나 스택오버플로우에서 복사한 코드

Stack Overflow나 블로그에서 찾은 코드를 그대로 쓰는 건 흔한 일이에요. 그런데 그 코드가 오래되었거나, 악의적으로 작성된 경우도 있어요.

> ⚠️ **이런 코드는 특히 주의하세요**
>
> - `eval()` 함수가 들어있는 코드 — 문자열을 코드로 실행해버려요
> - `document.write()`를 사용하는 코드 — 오래된 위험한 방식이에요
> - 출처 URL이 없거나 날짜가 5년 이상 지난 코드
> - 붙여넣었더니 작동은 하는데 왜 작동하는지 모르겠는 코드

### Claude에게 이렇게 요청해 보세요

- "이 코드를 어딘가에서 복사해왔는데 보안상 문제가 없는지 확인해줘."
- "eval이나 document.write 같은 위험한 함수가 있으면 더 안전한 방식으로 바꿔줘."

## 4. "AI가 만들어줬으니 괜찮겠지" 라는 착각

AI는 정말 많은 것을 잘 해요. 하지만 AI도 실수를 해요. 특히 보안 측면에서는, 우리가 요청하지 않으면 신경 쓰지 않는 경우가 많아요.

### AI가 흔히 빠뜨리는 것들

- **입력값 검증** — 사용자가 이상한 걸 입력해도 대비가 없음
- **에러 메시지 노출** — 에러 내용을 그대로 화면에 보여줘서 내부 정보가 새어나감
- **HTTPS 강제** — HTTP와 HTTPS를 구분 없이 처리
- **보안 헤더 설정** — Content-Security-Policy 같은 설정을 빠뜨림

### AI가 잘못된 코드를 자신 있게 줄 때도 있어요

AI는 틀린 코드도 자신 있게 설명해줘요. 특히 보안 관련 코드는 겉으로 보기에 멀쩡해 보여도 구멍이 있을 수 있어요. 그래서 보안이 중요한 기능이라면 반드시 따로 검토가 필요해요.

> 🔍 **AI가 만든 코드를 받았을 때 스스로 확인해보세요**
>
> - 입력창(input)이 있다면 → 이상한 값을 입력해봤을 때 어떻게 되는지 테스트해봤나요?
> - 외부 서비스를 연결했다면 → API 키가 코드 안에 노출되어 있지는 않나요?
> - 남의 코드를 복사했다면 → 그 코드가 뭘 하는 코드인지 Claude에게 설명 들었나요?

## 5. Claude에게 처음부터 잘 부탁하는 방법

가장 좋은 방법은 처음 요청할 때부터 보안을 함께 언급하는 거예요. 그러면 Claude가 보안까지 고려해서 코드를 작성해줘요.

### 이런 표현을 추가해보세요

❌ **보안 언급 없이 요청**

> "사용자 이름을 입력받아서 인사 메시지를 보여주는 웹페이지 만들어줘"

✅ **보안 포함해서 요청**

> "사용자 이름을 입력받아서 인사 메시지를 보여주는 웹페이지 만들어줘. XSS 같은 보안 문제도 고려해서 만들어줘"

### 코드를 받은 후에도 이렇게 물어보세요

- "방금 만들어준 코드에서 보안상 신경 써야 할 부분이 있으면 알려줘."
- "이 코드를 실제 인터넷에 올린다면 추가로 뭘 더 챙겨야 해?"
- "이 코드에서 사용자 입력을 처리하는 부분이 있으면 안전한지 확인해줘."
- "API 키나 비밀번호 같은 민감한 정보가 코드 어딘가에 노출되어 있으면 알려줘."

## 마무리하며

보안은 전문가만의 영역이 아니에요. 몇 가지 기본 습관만 들여도 대부분의 흔한 실수를 막을 수 있어요.

가장 중요한 건 처음부터 Claude에게 잘 물어보는 거예요. "보안도 신경 써서 만들어줘" 한 마디로 훨씬 안전한 코드를 받을 수 있거든요.

- 외부 코드는 출처 확인하기
